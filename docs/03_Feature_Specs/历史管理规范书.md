# 🕰️ 历史记录与快照管理规范书 (History & Snapshot Spec)

> **文档版本**: v2.0 (深度重构版)
> **技术对齐**: `server/src/services/ai.service.ts` -> `generateSnapshotSummary`
> **核心机制**: 时间机器 (Time Machine) 版本回溯

---

## 1. 快照触发机制 (The Snapshot Trigger)

为了平衡存储开销与安全性，系统在以下关键节点触发快照创建：
1.  **全局渲染完成**: AI 批量生成图片后。
2.  **大纲结构变更**: 用户手动拖拽或修改大纲节点。
3.  **视觉风格切换**: 更换模板或重新执行 Smart Refine。

## 2. 变更摘要自动生成协议 (AI Summary Protocol)

系统不仅仅存储状态，还会为每个快照配备一份人性化的摘要。

### 2.1 摘要生成逻辑
- **输入**: 提供变更前后的 `diffContext`。
- **AI 约束**: 调用 `gemini-3-pro-preview` 执行极简总结。
    - **字数**: 必须在 20 字以内。
    - **重点**: 捕捉“操作意图”（如：“修改了封面标题”、“更换为科技风格”）。
    - **Fallback**: 若无变化信息，返回“常规保存”。

## 3. 版本回溯流程 (The Rollback Flow)

1.  **状态隔离**: 每次快照存储的是项目的全量 JSON JSON Payload（包括所有 Slide 内容及样式配置）。
2.  **一键覆盖**: 用户点击“恢复”时，后端将 `ProjectSnapshot.data` 直接写回 `Project` 和 `Slide` 表。
3.  **副作用处理**: 恢复旧版本**不会**删除已存在的新版本快照，支持在不同时间节点间自由穿梭。

# 📋 大纲生成规范书 (Outline Generation Spec)

> **文档版本**: v2.0 (深度重构版)
> **技术对齐**: `server/src/services/ai.service.ts` -> `generateOutline`
> **核心逻辑**: 动态配比校准与页序引导算法

---

## 1. 结构化校准算法 (Dynamic Calibration)

系统在接收到用户设定的目标页数 (`targetPageCount`) 后，不会简单地将其传递给 AI，而是通过内部数学公式进行校准，确保生成的大纲在逻辑上保持闭环。

### 1.1 自动配比公式
系统将页面分为“固定页”与“可变页（正文）”：
- **固定页总数 (fixedSum)** = `cover` + `directory` + `transition` + `end`
- **正文页数 (content)** = `max(1, targetPageCount - fixedSum)`

### 1.2 Prompt 约束逻辑
在 `generateOutline` 函数中，系统会强制要求 AI 遵守以下约束：
1.  **JSON 严格对齐**: 返回的数组长度必须等于 `targetPageCount`。
2.  **类型闭环**: `pageType` 字段仅允许 `cover`, `directory`, `transition`, `content`, `end`。

## 2. 页面顺序引导协议 (Sequence Guidance)

系统采用内建的顺序引导算法（Recommendation Sequence），在 Prompt 中显式定义每一页的类型，引导 AI 进行逻辑重组。

### 2.1 引导流生成逻辑
- **头部 (Head)**: 封面 + 目录。
- **主体布局 (Body)**:
    - 若 `transition = 0`: 全部填充 `content`。
    - 若 `transition > 0`: 系统执行 **均匀切片算法**（`groupSize = floor(contents / (transitions + 1))`），在内容页之间平滑插入过渡页。
- **尾部 (Tail)**: 结束页。

### 2.2 真实 Prompt 指令片段
```text
【推荐页面顺序指南 (必须遵守)】:
第 1 页: cover, 第 2 页: directory, 第 3 页: content, 第 4 页: content, 第 5 页: transition...
```

## 3. 产出规范 (Output Standard)

- **原子化数据格式**:
  ```json
  {
    "title": "页面标题",
    "brief": "作为生成正文的参考描述",
    "pageType": "content"
  }
  ```
- **语言强制**: 简体中文。
- **严禁 Markdown**: 输出必须为原始 JSON 字符串，禁止包裹 ```json 标签。

## 4. 增量维护与容错 (Maintenance & Fault Tolerance)

### 4.1 单页重生成 (Incremental Update)
- **触发**: 用户对特定卡片不满意时。
- **逻辑**: 系统调用 `generateSingleOutlineItem` 接口，在保持整体上下文（`topic`, `totalCount`）不变的情况下，仅针对特定 `index` 的项进行标题与简介的精准重写。

### 4.2 大纲回收站与记忆寻回 (Memory Recovery)
- **回收站**: 当用户删除某个大纲项时，系统将其存入 `deletedItemsPool`。
- **强制对齐时的恢复机制**: 在执行“强制对齐”补齐缺失结构时，系统会优先按 `index` + `pageType` 从回收站中寻回之前的标题和文字，避免 AI 重新生成带来的“语义震荡”。

### 4.3 智能草稿时光机
- **状态快照**: 系统定时将 `outlineItems` 及附件解析内容快照至 `localStorage`。
- **中断恢复**: 检测到异常退出后，支持一键找回上次编辑的所有结构与状态代码。

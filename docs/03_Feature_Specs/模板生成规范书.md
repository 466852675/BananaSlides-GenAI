# 🎨 模板生成规范书 (Template Generation Spec)

> **文档版本**: v2.0 (深度重构版)
> **技术对齐**: `server/src/services/ai.service.ts` -> `smartRefine`
> **核心机制**: Smart Refine (智能意图驱动润色)

---

## 1. Smart Refine: 意图驱动的 3 步转化流

不同于简单的文字修正，Smart Refine 是一个将模糊的用户输入（如“想要科技感”）转化为工业级视觉指令（Style Config）的过程。

### 1.1 协议触发
当类型设置为 `requirement` 时，系统会启动“视觉导演”角色，遵循特定的 Markdown 结构化协议进行输出。

### 1.2 Markdown 结构化协议 (The Schema)
AI 必须返回严格符合以下结构的 Markdown 源码，否则后续的 `extractPageSpecificRequirements` 函数将无法正确切片：

1.  **# [Role Name] AI 视觉指令**: 定义全局角色。
2.  **## 1. 核心定位**: 包含角色设定、应用场景、视觉关键词。
3.  **## 2. 总体视觉规范**: 定义设计美学、16 进制颜色方案 (HEX)、字体建议（标题/正文）及核心元素。
4.  **## 3. 页面类型详细指令**: 为 `[封面页]`, `[目录页]`, `[章节过渡页]`, `[内容页]`, `[结束页]` 提供专属的布局与氛围描述。

## 2. 内容优化逻辑 (Content Refinement)

当类型为 `content` 时，系统执行轻量化润色逻辑：
- **目标**: 使文稿更具“演讲感”（ Conciseness, Profession, Impact）。
- **规则**: 强制使用列表 (Bullet points) 或短句，并锁定输出语言为简体中文。

## 3. 模板注入与级联传播

- **注入流**: 生成的 Markdown 视觉指令被存储在项目的 `requirements` 字段中。
- **级联流**: 每当渲染具体 Slide 时，系统会实时根据当前 Slide 的 `pageType` 从总指令集中“切开”出对应的局部指令，注入到 L1-L4 Prompt 引擎中。

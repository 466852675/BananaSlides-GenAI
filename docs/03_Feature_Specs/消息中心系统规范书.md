# 📨 消息中心系统规范书 (Message Center Spec)

> **文档版本**: v1.0
> **技术对齐**: `server/src/services/message.service.ts`, `src/components/message/`
> **核心机制**: 多类型消息推送 + 用户偏好设置 + 智能归档

---

## 1. 系统概述

消息中心提供全场景消息触达能力，支持9大消息类型，覆盖订单、退款、AI任务、系统公告等全业务场景。

### 1.1 设计目标

- **全场景覆盖**: 支持业务全流程的消息通知
- **多渠道触达**: 站内信 + 邮件 + 浏览器通知
- **用户可控**: 支持消息偏好设置
- **智能管理**: 自动归档 + 过期清理

### 1.2 核心特性

| 特性 | 说明 |
|------|------|
| 实时性 | 消息实时推送，支持WebSocket（预留） |
| 可靠性 | 消息持久化存储，支持历史查询 |
| 灵活性 | 支持9种消息类型，可按类型开关 |
| 可追溯 | 支持消息状态追踪和业务关联 |

## 2. 消息类型体系

### 2.1 消息类型定义

| 类型 | 代码 | 触发场景 | 优先级 | 默认开启 |
|------|------|----------|--------|----------|
| **SYSTEM** | 系统通知 | 系统维护、功能更新、重要公告 | 高 | ✅ |
| **ORDER** | 订单通知 | 订单创建、支付成功、订单取消 | 高 | ✅ |
| **REFUND** | 退款通知 | 退款申请、审核结果、退款完成 | 高 | ✅ |
| **AI** | AI任务通知 | 生成开始、生成完成、生成失败 | 中 | ✅ |
| **POINTS** | 积分通知 | 积分变动、积分预警、积分到账 | 中 | ✅ |
| **VIP** | VIP通知 | 会员开通、会员到期、权益变更 | 中 | ✅ |
| **ACTIVITY** | 活动通知 | 营销活动、优惠券发放、限时优惠 | 低 | ❌ |
| **SECURITY** | 安全通知 | 登录提醒、密码修改、异常操作 | 高 | ✅ |
| **LEAD** | 线索通知 | 新线索分配、线索状态变更 | 中 | ✅ |

### 2.2 消息优先级策略

```
高优先级: SYSTEM, ORDER, REFUND, SECURITY
中优先级: AI, POINTS, VIP, LEAD
低优先级: ACTIVITY
```

**优先级处理规则**:
- 高优先级消息：立即推送，不合并
- 中优先级消息：可延迟5分钟，支持批量合并
- 低优先级消息：可延迟30分钟，支持批量合并

### 3.4 智能归档

#### 归档策略
- **自动归档**: 30天前的已读消息自动归档
- **手动归档**: 用户可手动归档任意消息
- **归档查询**: 支持查看已归档消息
- **归档恢复**: 支持将归档消息恢复到收件箱

#### 清理策略
- 软删除消息：30天后物理删除
- 归档消息：90天后物理删除
- 系统消息：180天后物理删除

## 4. 技术实现

### 4.1 数据库模型

#### UserMessage（用户消息表）
```prisma
model UserMessage {
  id          String        @id @default(uuid())
  userId      String
  type        MessageType   // SYSTEM, ORDER, REFUND, AI, POINTS, VIP, ACTIVITY, SECURITY, LEAD
  title       String
  content     String
  isRead      Boolean       @default(false)
  isArchived  Boolean       @default(false)
  isDeleted   Boolean       @default(false)
  bizType     String?       // 业务类型，关联具体业务
  bizId       String?       // 业务ID，支持跳转
  createdAt   DateTime      @default(now())
  readAt      DateTime?
  
  @@index([userId, isRead, isArchived, isDeleted])
  @@index([userId, type])
  @@index([createdAt])
}
```

#### MessageTemplate（消息模板表）
```prisma
model MessageTemplate {
  id        String      @id @default(uuid())
  code      String      @unique // 模板代码
  type      MessageType // 消息类型
  title     String      // 模板标题
  content   String      // 模板内容（支持变量）
  isActive  Boolean     @default(true)
  createdAt DateTime    @default(now())
  updatedAt DateTime    @updatedAt
}
```

#### UserMessageSettings（用户消息设置表）
```prisma
model UserMessageSettings {
  id            String   @id @default(uuid())
  userId        String   @unique
  emailEnabled  Boolean  @default(true)
  browserEnabled Boolean @default(false)
  typeSettings  Json     // 各类型开关状态
  createdAt     DateTime @default(now())
  updatedAt     DateTime @updatedAt
}
```

### 4.2 服务端服务

#### message.service.ts
核心消息服务，提供：
- `createMessage()` - 创建消息
- `getUserMessages()` - 获取用户消息列表
- `markAsRead()` - 标记已读
- `markAllAsRead()` - 全部已读
- `archiveMessage()` - 归档消息
- `deleteMessage()` - 删除消息
- `getUnreadCount()` - 获取未读数

#### message-settings.service.ts
消息设置服务，提供：
- `getSettings()` - 获取用户设置
- `updateSettings()` - 更新设置
- `getTypeSettings()` - 获取类型设置
- `updateTypeSettings()` - 更新类型设置

#### message-template.service.ts
消息模板服务，提供：
- `getTemplate()` - 获取模板
- `renderTemplate()` - 渲染模板（变量替换）
- `createTemplate()` - 创建模板（管理员）
- `updateTemplate()` - 更新模板（管理员）

#### message-archive.service.ts
消息归档服务，提供：
- `archiveOldMessages()` - 自动归档旧消息
- `cleanupDeletedMessages()` - 清理已删除消息
- `cleanupArchivedMessages()` - 清理归档消息

### 4.3 通知服务矩阵

系统提供8种专门的notification services：

| 服务 | 文件 | 职责 |
|------|------|------|
| ai-notification.service.ts | AI任务通知 | 大纲生成完成、图片生成完成、生成失败 |
| order-notification.service.ts | 订单通知 | 订单创建、支付成功、订单取消 |
| points-notification.service.ts | 积分通知 | 积分变动、积分预警、积分到账 |
| refund-notification.service.ts | 退款通知 | 退款申请提交、审核结果、退款完成 |
| admin-notification.service.ts | 管理员通知 | 系统异常、需要人工处理的事项 |
| vip-notification.service.ts | VIP通知 | 会员开通、会员到期、权益变更 |
| activity-notification.service.ts | 活动通知 | 营销活动、优惠券发放 |
| security-notification.service.ts | 安全通知 | 登录提醒、密码修改、异常操作 |

## 5. API 接口

### 5.1 用户接口

#### 获取消息列表
```http
GET /api/messages?page=1&limit=20&type=SYSTEM&isRead=false
```

#### 获取未读数
```http
GET /api/messages/unread-count
```

#### 标记已读
```http
POST /api/messages/{id}/read
```

#### 全部已读
```http
POST /api/messages/read-all
```

#### 归档消息
```http
POST /api/messages/{id}/archive
```

#### 删除消息
```http
DELETE /api/messages/{id}
```

#### 获取消息设置
```http
GET /api/messages/settings
```

#### 更新消息设置
```http
PUT /api/messages/settings
Content-Type: application/json

{
  "emailEnabled": true,
  "typeSettings": {
    "SYSTEM": true,
    "ORDER": true,
    "ACTIVITY": false
  }
}
```

### 5.2 管理员接口

#### 获取模板列表
```http
GET /api/admin/message-templates
```

#### 创建模板
```http
POST /api/admin/message-templates
Content-Type: application/json

{
  "code": "ORDER_CREATED",
  "type": "ORDER",
  "title": "订单创建成功",
  "content": "您的订单 {{orderNo}} 已创建成功，金额 {{orderAmount}} 元。"
}
```

#### 更新模板
```http
PUT /api/admin/message-templates/{id}
```

#### 发送系统公告
```http
POST /api/admin/system-announcement
Content-Type: application/json

{
  "title": "系统维护通知",
  "content": "系统将于今晚 00:00-02:00 进行维护升级。",
  "targetUsers": "all" // all | vip | specific-user-ids
}
```

## 6. 业务流程

### 6.1 消息发送流程

```
业务事件触发
    ↓
调用对应的 Notification Service
    ↓
查询消息模板
    ↓
渲染模板（变量替换）
    ↓
查询用户消息设置
    ↓
判断是否需要发送
    ↓
创建站内信
    ↓
判断是否需要邮件通知
    ↓
发送邮件（异步）
```

### 6.2 消息阅读流程

```
用户点击消息
    ↓
标记消息为已读
    ↓
更新未读计数
    ↓
显示消息详情
    ↓
提供业务跳转（如有）
```

### 6.3 自动归档流程

```
定时任务（每日凌晨）
    ↓
查询30天前的已读消息
    ↓
批量归档
    ↓
记录归档日志
```

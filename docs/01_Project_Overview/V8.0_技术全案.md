## 1. 🎯 产品规格书 (PRD)

本系统旨在构建一个**闭环的商业操作系统**，通过精细化运营实现用户增长与变现的双赢。

### 1.1 核心业务流程 (Core Flows)

#### A. 增长裂变 (Growth Engine)
1.  **每日签到 (Sticky)**:
    *   **入口**: 全局弹窗 / 个人中心 / 顶部 Nav 积分徽章。
    *   **交互**: 弹出日历 Modal，点击签到触发动效。
    *   **规则**:
        *   基础: **+50分/天**。
        *   阶梯: 连续3天 +100，连续7天 +200 (后台可配)。
        *   中断: 超过24小时未签重置为 Day 1。
2.  **拉新裂变 (Referral)**:
    *   **分享者**: 个人中心提供“专属邀请码”及“复制链接”。
    *   **受邀者**: 注册页输入邀请码 -> 注册成功 -> 获赠新手礼 (默认30分)。
    *   **奖励**: 受邀者**首次登录**成功 -> 邀请者实时获赠 **+200分** (后台可配)。

#### B. 智能分级预警 (Tiered Warnings)
系统实时监控用户积分余额，触发机制如下：

*   **触发阈值**: 剩余积分 **≤ 50** (后台 `WARN_THRESHOLD` 可配，允许 ±20 浮动)。
*   **分层策略**:
    | 用户角色 | 场景：余额告急 (≈50) | 行动点 (CTA) | 交互形式 |
    | :--- | :--- | :--- | :--- |
    | **普通用户** | "体验分即将耗尽，升级解锁无限创作" | **升级 Pro 会员** | Toast + 引导弹窗 |
    | **Pro 用户** | "本月额度紧缺，加油包助您续航" | **购买积分加油包** | Toast + 引导弹窗 |
    | **企业成员** | "团队余额不足，请联系管理员" | **复制管理员信息** | 仅 Toast 提示 |
    | **(任意) 0分** | "积分耗尽，无法继续生成" | **强制阻断** | 模态弹窗 (不可关闭) |

*   **消耗预显**: 在所有 AI 按钮（大纲/PPT/润色）旁悬停显示 `⚡ -20`。

#### C. 全能运营后台 (Operation OS)
运营人员通过 GUI 掌控一切，脱离数据库操作。
1.  **商品中心**: 上架/下架会员卡、加油包；修改价格、赠送积分、角标。
2.  **规则引擎**: 调整签到奖励、拉新奖励，以及所有 AI 动作的扣费单价。
3.  **用户运维**: 封禁违规账号、手动充值/扣费 (带审计备注)。
4.  **全局配置**: 一键开启/关闭系统维护模式、注册邀请制模式。

## 2. 🏗️ 数据库架构设计 (Schema V8)

```prisma
// server/prisma/schema.prisma (Incremental)

// 1. 全局配置字典
model GlobalConfig {
  key       String   @id // e.g., "SYSTEM_MAINTENANCE", "WARN_THRESHOLD"
  value     String   // "true", "50"
  category  String   // "SYSTEM", "RISK", "UI"
  desc      String?
  updatedAt DateTime @updatedAt
}

// 2. 商品模型 (支持营销)
model Product {
  id            String   @id @default(uuid())
  type          String   // VIP_MONTHLY, POINTS_PACK
  name          String
  originalPrice Float?   // 划线价
  price         Float    // 售价
  points        Int      // 包含积分
  tags          String?  // JSON: ["HOT", "LIMITED"]
  discountEnd   DateTime? // 倒计时截止
  isActive      Boolean  @default(true)
  sortOrder     Int      @default(0)
}

// 3. 用户扩展
model User {
  // ... existing fields ...
  inviteCode    String?   @unique
  invitedById   String?
  checkInDate   DateTime? // Last check-in date
  checkInStreak Int       @default(0)
  riskScore     Int       @default(0) // 风控分
}

// 4. 签到流水 (防刷 & 统计)
model CheckInLog {
  id        String   @id @default(uuid())
  userId    String
  date      String   // "2026-01-27"
  points    Int
  streak    Int
  createdAt DateTime @default(now())
  @@unique([userId, date])
}

// 5. 积分规则增强
model PointsRule {
  code        String   @id // OUTLINE_GEN, CHECK_IN_BASE
  costPoints  Int      // 正数扣费，负数赠送(如 -50)
  isEnabled   Boolean  @default(true)
  name        String
}
```

## 3. 🔌 AI 引擎与契约 (AI Engine & Contracts)

### 3.1 混合模型路由协议 (Hybrid Router)
系统采用 **Adapter 模式** 实现多模型无缝热切换：
*   **Gemini Native**: 支持 Google 全系 SDK。内置 `gemini-3-*` 别名路由，自动平衡 **Gemini 2.0/1.5** 系列性能。
*   **Volcengine Ark**: 深度适配火山引擎。支持推理接入点 ID 配置，内置**分辨率自动补全**逻辑（确保达到生图最低像素阈值）及 **Seed 锁定**（保持风格一致性）。
*   **MinerU Engine**: 工业级 PDF/Word 解析内核，支持复杂的版式识别与 Markdown 高保真导出。

### 3.2 积分计费体系 (Economic Engine)
基于 `PointsActionCode` 的细粒度计费：
- `outline_generation`: 全局大纲构建
- `outline_page_regen`: 单页大纲增量重写
- `slide_content`: AI 内容批量详化渲染
- `slide_image`: 4层级 Prompt 图片生成
- `doc_parse`: 文档语义解构 (MinerU)
- `smart_refine`: 创意描述润色

### 3.3 审计与安全 (Audit)
- **事务处理**: 采用“充值-消费”流水审计，每一笔调账必须关联 `operatorId`。
- **UI 反馈**: 引入 `ConfirmDialog` 优化敏感操作（如：**退款操作内置文本输入理由**）。

## 3. 🔌 API 契约与逻辑 (Contracts)

### 3.1 客户端 API
*   `POST /api/growth/check-in`: 执行签到 (含阶梯逻辑)。
*   `GET /api/products`: 获取上架商品 (含营销角标)。
*   `GET /api/points/status`: 获取当前余额及预警状态 (Redux/Context 轮询)。

### 3.2 管理端 API (Admin Only)
*   `GET /api/admin/config`: 获取全量配置。
*   `PUT /api/admin/config`: 批量更新 (如修改 `WARN_THRESHOLD` 为 60)。
*   `PATCH /api/admin/products/:id`: 改价/下架。
*   `POST /api/admin/users/:id/adjust`: 手动调账 (写入 Transaction: `type=ADMIN_ADJUST`).

## 5. ✅ 质量验收标准 (Acceptance Criteria)

1.  **数据一致性**: 管理员后台修改 `OUTLINE_GEN` 为 100 分，前台用户（不刷新页面）点击生成时，服务端应拦截并按 100 分扣除，前端应通过 Global Error Handler 捕获并提示"价格已变动"。
2.  **风控有效性**: 同一 IP 连续注册 5 个账号并填写同一邀请码，第 6 个账号不应触发奖励，且标记主账号 `riskScore`。
3.  **财务审计**: 每一笔积分变动（包括管理员手调）都必须能在 `My Points` 页面查到明细，流水号唯一。
4.  **交互闭环**: 积分不足 -> 弹窗购买 -> 支付成功 -> 弹窗关闭 -> 余额刷新 -> 继续之前的 AI 操作 (Resume)。

# 🏗️ YH-AI PPT 系统架构概述

> **文档状态**: ✅ 已发布  
> **版本**: v2.0 (与PRD v2.0对齐)  
> **最后更新**: 2026-02-16  

本文档提供YH-AI PPT系统的整体架构视图，包括分层架构、核心组件关系、数据流向等宏观设计。

---

## 1. 架构总览

### 1.1 系统分层架构

```mermaid
graph TB
    subgraph 接入层
        LB[负载均衡/Nginx]
        CDN[CDN静态资源]
    end
    
    subgraph 网关层
        GW[API Gateway]
        AUTH[统一认证]
        RATE[限流/风控]
    end
    
    subgraph 服务层
        WEB[前端服务<br/>React 19.2]
        API[后端API服务<br/>Express 5.2]
        AI[AI服务<br/>多模型路由]
        ADMIN[管理后台<br/>独立前端]
    end
    
    subgraph 数据层
        DB[(SQLite<br/>Prisma ORM)]
        CACHE[(内存缓存)]
        FILE[文件存储]
    end
    
    subgraph 外部服务
        GEMINI[Google Gemini]
        VOLC[火山引擎]
        ALIPAY[支付宝]
        WECHAT[微信支付]
        SMTP[邮件服务]
    end
    
    LB --> GW
    CDN --> WEB
    GW --> AUTH
    AUTH --> RATE
    RATE --> WEB
    RATE --> API
    RATE --> ADMIN
    
    WEB --> API
    ADMIN --> API
    API --> AI
    
    API --> DB
    API --> CACHE
    API --> FILE
    
    AI --> GEMINI
    AI --> VOLC
    API --> ALIPAY
    API --> WECHAT
    API --> SMTP
```

### 1.2 核心架构特征

| 特征 | 描述 | 技术实现 |
|------|------|----------|
| **前后端分离** | 独立部署、独立开发 | React SPA + RESTful API |
| **微服务化** | AI服务独立部署 | 独立AI路由服务 |
| **多层安全** | 认证/授权/风控分层 | JWT + RBAC + 风控中间件 |
| **数据一致性** | 事务保证 | SQLite + Prisma事务 |
| **缓存策略** | 多级缓存 | 内存缓存 + 浏览器缓存 |

## 3. 数据流向

### 3.1 典型业务流程

#### 3.1.1 PPT生成流程

```mermaid
sequenceDiagram
    participant U as 用户
    participant F as 前端
    participant API as 后端API
    participant AI as AI服务
    participant DB as 数据库
    participant EXT as 外部AI
    
    U->>F: 输入主题
    F->>API: POST /api/outline/generate
    API->>DB: 检查积分
    API->>DB: 扣除积分
    API->>AI: 调用文本模型
    AI->>EXT: 生成大纲
    EXT-->>AI: 返回大纲
    AI-->>API: 结构化大纲
    API->>DB: 保存大纲
    API-->>F: 返回大纲
    F-->>U: 展示大纲
    
    U->>F: 确认生成PPT
    F->>API: POST /api/project/generate
    API->>DB: 创建幻灯片记录
    API->>AI: 批量生成图片
    loop 每页幻灯片
        AI->>EXT: 调用生图模型
        EXT-->>AI: 返回图片URL
        AI->>DB: 保存图片
    end
    AI-->>API: 生成完成
    API->>DB: 更新项目状态
    API-->>F: 返回完成通知
    F-->>U: 展示结果
```

#### 3.1.2 订单支付流程

```mermaid
sequenceDiagram
    participant U as 用户
    participant F as 前端
    participant API as 后端API
    participant ORDER as 订单服务
    participant PAY as 支付服务
    participant DB as 数据库
    participant EXT as 支付渠道
    
    U->>F: 选择商品
    F->>API: POST /api/orders
    API->>ORDER: 创建订单
    ORDER->>DB: 保存订单
    ORDER-->>API: 返回订单
    API-->>F: 返回支付参数
    
    F->>U: 唤起支付
    U->>EXT: 完成支付
    EXT-->>API: 支付回调
    API->>PAY: 处理回调
    PAY->>DB: 更新订单状态
    PAY->>ORDER: 发放权益
    ORDER->>DB: 增加积分/VIP
    ORDER-->>API: 完成
    API-->>F: 推送通知
    F-->>U: 显示成功
```

## 5. 扩展性设计

### 5.1 水平扩展能力

| 组件 | 扩展方式 | 状态 |
|------|---------|------|
| **前端** | CDN + 多实例 | ✅ 支持 |
| **后端API** | 负载均衡 + 多实例 | ✅ 支持 |
| **数据库** | 读写分离（SQLite限制） | ⚠️ 需迁移 |
| **文件存储** | NAS/OSS | ✅ 支持 |
| **AI服务** | 独立服务 + 队列 | ✅ 支持 |

### 5.2 未来演进方向

1. **数据库迁移**: SQLite → PostgreSQL（支持更高并发）
2. **缓存升级**: 本地缓存 → Redis集群
3. **消息队列**: 引入RabbitMQ/Kafka处理异步任务
4. **微服务拆分**: 将AI服务、支付服务独立部署

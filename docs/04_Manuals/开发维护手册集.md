# 🛠️ 开发维护手册集 (Developer & Maintenance Notes)

> **文档版本**: v2.0 (深度重构版)
> **涉及文件**: `server/src/app.ts`, `server/src/services/ai.service.ts`
> **核心机制**: Router-Adapter 适配与生产级热加载

---

## 1. 模型路由适配层 (Router-Adapter)

系统通过 `getTaskConfig` 函数实现了一套工业级的模型调度逻辑，支持在全球顶尖模型之间无缝热切换。

### 1.1 优先级调度策略
1.  **CustomCombo (任务定制)**: 若设置中开启 CustomCombo，优先使用为特定任务（Text/Image/Vision）绑定的私有连接。
2.  **General Settings (全局偏好)**: 降级到全局统一配置的模型 ID。
3.  **Adaptive Default (自适应回退)**: 若上述均缺失，系统将自动映射以下默认值：
    - `text` -> `gemini-3-pro-preview`
    - `image` -> `gemini-3-pro-image`
    - `vision` -> `gemini-3-flash`

### 1.2 协议仲裁 (`shouldUseGeminiNative`)
系统会自动识别 API 地址。若检测到 `googleapis.com`，则调用底层的 Google GenAI SDK；若检测到 `/v1` 结尾，则自动切换为标准的 OpenAI REST API 封装库。

## 2. 核心链路集成: MinerU 与 Vision 降级

文件解析链路采用了具备高度冗余的设计：

1.  **MinerU 内切 (一级链路)**: 处理 PDF 时，优先调用 `MinerUService` 进行多栏语义解析。
2.  **Vision Fallback (二级降级)**: 若 MinerU 返回失败或未配置 Key，系统自动将文件转化为高清 Base64 图片，调用 `gemini-3-flash` 进行视觉语义提取。

## 3. 生产级运维：设置热加载 (Hot Reload)

在 `server/src/app.ts` 中实现了一套生产级的配置监听机制，无需重启服务即可变更核心参数。

### 3.1 `.env` 实时监听
- **机制**: 使用 `fs.watch` 锁定项目根目录的 `.env` 文件。
- **消抖处理**: 内核具备 500ms 的 `Debounce` 逻辑，防止因编辑器多次保存触发的性能抖动。
- **自动互刷**: 变更检测后，系统触发 `SettingService.syncEnvToDatabase()`，自动将 `.env` 的新 Key 或模型 ID 同步至本地 SQL 数据库。

> **文档状态**: 设计方案

## 一、设计目标

### 1.1 现状痛点
- 当前仅 **33 个权限**，覆盖约 **50%** 的功能点
- 权限粒度不均（CREATION 模块 8 个，LEADS 仅 1 个）
- 部分功能无权限控制（签到、邀请、回收站等）
- 权限命名规范不一致

### 1.2 设计目标
- 建立 **80+ 权限** 的完整体系
- 实现**功能级**权限控制（每个重要操作都可授权）
- 统一**命名规范**（`{module}.{action}.{target}`）
- 区分**用户侧/管理侧**权限
- 支持**数据范围**控制（只能看自己的/看部门的/看全部的）

---

## 二、权限架构设计

### 2.1 权限模型

```
权限(Permission)
  ├── 模块(Module) - 功能分类
  ├── 操作(Action) - 具体操作
  ├── 目标(Target) - 操作对象
  ├── 范围(Scope) - 数据范围
  └── 类型(Type) - 功能/数据/菜单
```

### 2.2 权限命名规范

**格式**: `{domain}.{module}.{action}.{target}`

| 层级 | 含义 | 示例 |
|------|------|------|
| domain | 领域 | `user` (用户侧), `admin` (管理侧) |
| module | 模块 | `projects`, `orders`, `templates` |
| action | 操作 | `view`, `create`, `update`, `delete`, `export` |
| target | 目标 | `own` (自己的), `all` (全部), `department` (部门) |

**示例**:
- `user.projects.view.own` - 查看自己的项目
- `admin.users.manage.all` - 管理所有用户
- `admin.orders.refund.all` - 给任何订单退款

### 2.3 权限类型分类

| 类型 | 说明 | 示例 |
|------|------|------|
| **Menu** | 菜单可见性 | 左侧菜单栏显示控制 |
| **Function** | 功能操作 | 按钮点击、API 调用 |
| **Data** | 数据范围 | 只能看自己的数据 |
| **Field** | 字段级 | 敏感字段可见性 |

## 四、权限粒度规范

### 4.1 粒度分级

| 级别 | 说明 | 适用场景 |
|------|------|---------|
| **L1 - 模块级** | 整个模块的访问控制 | 菜单显示 |
| **L2 - 功能级** | 具体功能操作控制 | 按钮显示、API权限 |
| **L3 - 数据级** | 数据范围控制 | 列表筛选、详情查看 |
| **L4 - 字段级** | 敏感字段控制 | 手机号、余额等 |

### 4.2 数据范围定义

| 范围 | 代码 | 说明 |
|------|------|------|
| 仅自己 | `own` | 只能操作自己的数据 |
| 本部门 | `dept` | 只能看本部门数据 |
| 全部 | `all` | 可以看所有数据 |

### 6.2 后端实施规范

#### 6.2.1 中间件权限校验

```typescript
// 权限校验中间件
export const requirePermission = (permissionCode: string) => {
  return async (req: Request, res: Response, next: NextFunction) => {
    const userId = req.user?.id;
    
    // 查询用户权限
    const hasPermission = await PermissionService.checkPermission(
      userId, 
      permissionCode
    );
    
    if (!hasPermission) {
      return res.status(403).json({
        code: 'FORBIDDEN',
        message: `权限不足: 需要 ${permissionCode} 权限`
      });
    }
    
    next();
  };
};

// 路由使用
router.put('/users/:id/status', 
  authenticate, 
  requirePermission('admin.users.manage.status'),
  updateUserStatus
);
```

#### 6.2.2 数据范围过滤

```typescript
// 服务层自动过滤
export class UserService {
  static async listUsers(userId: string, dataScope: string) {
    const user = await prisma.user.findUnique({ where: { id: userId } });
    
    let whereClause = {};
    
    switch (dataScope) {
      case 'own':
        // 只能看自己
        whereClause = { id: userId };
        break;
      case 'dept':
        // 看本部门
        whereClause = { departmentId: user.departmentId };
        break;
      case 'all':
        // 看全部
        whereClause = {};
        break;
      default:
        whereClause = { id: userId };
    }
    
    return prisma.user.findMany({ where: whereClause });
  }
}
```

#### 6.2.3 超级管理员绕过

```typescript
// 超级管理员拥有所有权限
export const checkPermission = async (userId: string, permissionCode: string) => {
  const user = await prisma.user.findUnique({ 
    where: { id: userId },
    include: { rolePermissions: { include: { permission: true } } }
  });
  
  // 超级管理员直接通过
  if (user.role === 'SUPER_ADMIN') {
    return true;
  }
  
  // 检查具体权限
  return user.rolePermissions.some(
    rp => rp.permission.code === permissionCode
  );
};
```

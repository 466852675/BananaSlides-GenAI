# ⚙️ 系统配置规范书 (System Configuration Spec)

> **文档版本**: v2.0 (深度重构版)
> **技术对齐**: `server/src/services/setting.service.ts`
> **核心机制**: 多级配置互刷与并发调优

---

## 1. 配置互刷协议 (Config Synchronization)

系统通过 `AppSettings` 模型维护全局运行状态，并执行双向同步逻辑。

### 1.1 环境变量优先权
启动时，`syncEnvToDatabase` 函数执行以下逻辑：
- **检测**: 扫描根目录 `.env`。
- **对齐**: 若环境变量中存在 `GEMINI_API_KEY` 或自定义 `BASE_URL`，系统将**强制改写**数据库中的全局配置，确保运维人员的紧急调整具有最高权威。

### 1.2 热重载触发流程 (Hot Swap)
1.  用户通过配置面板点击“保存”。
2.  后端更新 `AppSettings` 记录。
3.  系统触发全局缓存刷新。
4.  后续的 `getTaskConfig` 请求将即时捕获新模型 ID。

## 2. 工业级并发控制 (Concurrency Engine)

为了在速度与 API 稳定性（429 Rate Limit）之间取得平衡，系统提供了可配置的并发策略：

- **Text Concurrency (默认 10)**: 逻辑推理支持高并发，通过 `p-limit` 级思想控制请求队列。
- **Image Concurrency (默认 2)**: **低频并发锁定。** 由于生图模型耗时较长且对并发限制严苛，系统建议设置为 1-2，确保生成稳定性。
- **Vision Concurrency (默认 2)**: 视觉解析属于中等开销，支持多线程并发执行风格提取。

## 3. 分辨率驱动策略与火山引擎优化

系统根据应用场景动态调整生成的分辨率，并针对特定提供商执行**自动补偿**：
- **火山引擎 (Volcengine)**: 针对“即梦”等生图接口，系统会自动将低分辨率请求补足至模型要求的最低像素阈值（约 360w 像素），并执行 **Seed 锁定** 以确保同一项目内的视觉一致性。
- **动态分档**:
    - **1K 档位**: 1280x720 等。
    - **2K 档位**: 2048x2048 / 1920x1080 等。
    - **4K 档位**: 3840x2160 / 4096x4096 (由 `IMG_RESOLUTION` 全局定义)。

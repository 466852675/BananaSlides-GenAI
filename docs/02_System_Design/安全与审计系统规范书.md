# 🛡️ 安全与审计系统规范书 (Security & Audit Spec)

> **文档版本**: v1.0
> **技术对齐**: `server/src/services/audit.service.ts`, `server/src/utils/`
> **核心机制**: 多层防护 + 全量审计 + 智能风控

---

## 1. 系统概述

安全与审计系统提供多层次的安全防护机制，包括内容过滤、Prompt注入检测、操作审计和风控评分。

### 1.1 设计目标

- **内容安全**: 防止违规内容和恶意Prompt
- **操作审计**: 全量记录敏感操作，支持追溯
- **访问控制**: 细粒度权限管理和限流保护
- **风险防控**: 用户行为分析和异常检测

### 1.2 核心特性

| 特性 | 说明 |
|------|------|
| 内容过滤 | 敏感词检测、违规内容识别 |
| Prompt安全 | 注入检测、越狱攻击防护 |
| 全量审计 | 所有敏感操作留痕 |
| 智能风控 | 基于行为的风险评分 |
| 分层限流 | 多层级API速率限制 |

## 3. 审计日志系统

### 3.1 审计范围

#### 记录的操作类型
| 类型 | 说明 | 示例 |
|------|------|------|
| AUTH | 认证操作 | 登录、登出、密码修改 |
| USER | 用户管理 | 创建用户、修改权限 |
| ORDER | 订单操作 | 创建订单、支付、退款 |
| POINTS | 积分操作 | 积分调整、积分规则修改 |
| PROJECT | 项目操作 | 创建项目、删除项目 |
| AI | AI生成 | 大纲生成、图片生成 |
| ADMIN | 管理操作 | 系统配置修改 |
| SECURITY | 安全事件 | 异常登录、权限越界 |

#### 不记录的操作
- 普通查询操作
- 已授权的正常业务操作
- 静态资源访问

### 3.2 审计字段

```prisma
model AuditLog {
  id          String        @id @default(uuid())
  userId      String?       // 操作人ID（匿名操作为null）
  type        AuditType     // 操作类型
  action      String        // 具体动作
  content     String        // 操作内容（JSON）
  severity    Severity      // 严重程度
  ip          String        // 操作IP
  userAgent   String        // 客户端信息
  status      String        // 操作结果（success/failure）
  errorMessage String?      // 错误信息
  createdAt   DateTime      @default(now())
  
  @@index([userId])
  @@index([type])
  @@index([severity])
  @@index([createdAt])
}
```

#### 严重程度定义
| 级别 | 说明 | 示例 |
|------|------|------|
| INFO | 普通信息 | 正常登录 |
| WARNING | 警告 | 密码错误次数过多 |
| ERROR | 错误 | 操作失败 |
| CRITICAL | 严重 | 权限越界、数据泄露 |

### 3.3 审计查询

#### 查询维度

## 4. 风控系统

### 4.1 用户风控分 (riskScore)

#### 计算因素
| 因素 | 权重 | 说明 |
|------|------|------|
| 退款频率 | 30% | 退款次数/订单次数 |
| 退款金额 | 20% | 退款金额/消费金额 |
| 异常登录 | 25% | 异地登录、频繁登录失败 |
| 操作频率 | 15% | 异常高频操作 |
| 投诉记录 | 10% | 被投诉次数 |

#### 风险等级
| 分数 | 等级 | 处理策略 |
|------|------|----------|
| 0-30 | 低风险 | 正常服务 |
| 31-60 | 中风险 | 加强监控 |
| 61-80 | 高风险 | 限制部分功能 |
| 81-100 | 极高风险 | 账号冻结 |

### 4.2 风控策略

#### 自动策略
- 高风险用户：限制退款、限制积分获取
- 异常登录：要求二次验证
- 高频操作：触发验证码

#### 人工介入
- 极高风险账号人工审核
- 异常大额退款人工审核
- 投诉处理

## 6. 密码安全

### 6.1 密码策略

| 策略 | 要求 |
|------|------|
| 最小长度 | 8位 |
| 复杂度 | 必须包含字母和数字 |
| 历史密码 | 不能与前3次重复 |
| 过期时间 | 90天（预留） |

### 6.2 密码存储

使用 bcryptjs 进行哈希存储：
```typescript
// 哈希密码
const hashedPassword = await bcrypt.hash(password, 10);

// 验证密码
const isValid = await bcrypt.compare(password, hashedPassword);
```

## 7. 权限控制

### 7.1 JWT Token

#### Token结构
```typescript
interface JWTPayload {
  userId: string;
  email: string;
  role: UserRole;
  permissions: string[];
  iat: number;  // 签发时间
  exp: number;  // 过期时间
}
```

#### Token策略
- 访问Token：7天有效期
- 刷新Token：30天有效期
- Token黑名单：支持强制失效

### 7.2 细粒度权限

#### 权限检查中间件
```typescript
// 检查单个权限
authMiddleware.requirePermission('users:view')

// 检查多个权限（任一）
authMiddleware.requireAnyPermission(['users:view', 'users:admin'])

// 检查多个权限（全部）
authMiddleware.requireAllPermissions(['users:view', 'users:update'])
```

## 8. 安全事件响应

### 8.1 事件分级

| 级别 | 说明 | 响应时间 |
|------|------|----------|
| P0 | 严重安全事件（数据泄露、系统入侵） | 立即 |
| P1 | 高危事件（大规模攻击、核心功能异常） | 1小时内 |
| P2 | 中危事件（个别账号异常、小范围攻击） | 4小时内 |
| P3 | 低危事件（日志异常、非关键告警） | 24小时内 |

### 8.2 应急响应流程

```
发现安全事件
    ↓
立即启动应急预案
    ↓
隔离受影响系统
    ↓
分析事件原因
    ↓
修复漏洞
    ↓
恢复服务
    ↓
事后复盘
```

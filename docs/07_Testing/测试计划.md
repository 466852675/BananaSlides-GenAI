## 1. 测试金字塔与策略

本计划采用 **4层测试模型**，确保从底层逻辑到用户感知的全面覆盖。

| 层级 | 测试类型 | 覆盖率目标 | 工具 | 关注点 |
|:---|:---|:---|:---|:---|
| **L4** (顶层) | **E2E 验收测试** | 核心路径 100% | Playwright | 真实用户旅程、跨页面交互、视觉回归 |
| **L3** | **集成与 API 测试** | 接口 100% | Postman/Jest | 数据契约、权限鉴权、错误码规范 |
| **L2** | **业务逻辑测试** | 复杂逻辑 100% | Jest/Mocha | 订单状态机、积分计算、AI Prompt 组装逻辑 |
| **L1** (底层) | **单元测试** | 工具类 80% | Vitest | 正则表达式、数据转换工具 |

### 1.2 强制执行工具 (Mandatory Execution Tool)

> 🛑 **严令禁止**: 
> 1. 严禁运行本地 `npx playwright test` 脚本（因 headless 环境差异导致结果不可靠）。
> 2. 严禁手动操作或使用非 Playwright 工具。
>
> **所有测试必须且只能使用 Playwright MCP 工具 (`@mcp:playwright`) 实时执行。**
> 1.  **Agent 驱动**: 由 AI Agent 通过 MCP 协议直接操控浏览器，实现“所见即所得”的验证。
> 2.  **全链路模拟**: 必须模拟 `navigate -> click -> type` 的完整真实用户路径。
> 3.  **截图存证**: 每一步关键操作必须调用 `browser_snapshot` 或 `take_screenshot` 保存证据。
> 4.  **统一入口**: 所有测试的 Base URL 必须严格锁定为 `http://localhost:1000/`。

## 常见问题

### 🔴 服务无法启动

**症状**: `docker-compose up` 后服务立即退出

**排查步骤**:

1. **查看日志**
```bash
docker-compose logs backend
```

2. **检查环境变量**
```bash
# 确认 .env 文件存在
cat .env | grep -E '^(JWT_SECRET|DATABASE_URL)'

# 检查变量格式
```

3. **检查端口占用**
```bash
# 查看1111端口是否被占用
sudo lsof -i :1111

# 释放端口
sudo kill -9 <PID>
```

**解决方案**:
- 确保 `.env` 文件存在且配置正确
- 确保端口未被其他程序占用
- 检查磁盘空间是否充足

---

### 🔴 数据库连接失败

**症状**: 错误信息包含 "Database connection failed" 或 "SQLite Error"

**排查步骤**:

1. **检查数据库文件**
```bash
# 检查文件是否存在
ls -la server/prisma/*.db

# 检查文件权限
chmod 644 server/prisma/dev.db
```

2. **验证数据库完整性**
```bash
cd server
sqlite3 prisma/dev.db "PRAGMA integrity_check;"
```

3. **检查磁盘空间**
```bash
df -h
```

**解决方案**:
```bash
# 方案1: 修复数据库
sqlite3 prisma/dev.db ".recover" | sqlite3 prisma/dev.db.fixed
mv prisma/dev.db prisma/dev.db.backup
mv prisma/dev.db.fixed prisma/dev.db

# 方案2: 重置数据库（⚠️ 数据丢失）
npx prisma db push --force-reset
npx prisma db seed
```

### 🔴 AI 生成失败

**症状**: 生成大纲/图片时提示错误或长时间无响应

**排查步骤**:

1. **检查 API Key**
```bash
# 查看环境变量
echo $GEMINI_API_KEY

# 测试 API 连接
curl -H "Authorization: Bearer $GEMINI_API_KEY" \
  https://generativelanguage.googleapis.com/v1beta/models
```

2. **查看详细错误日志**
```bash
# 后端日志
docker-compose logs backend | grep -i "ai\|generate\|error"

# 查看最近错误
journalctl -u yh-ai-ppt -n 100 | grep ERROR
```

3. **检查网络连接**
```bash
# 测试外网连接
ping google.com

# 测试 API 可达性
curl -I https://generativelanguage.googleapis.com
```

**解决方案**:

| 问题 | 解决方案 |
|------|---------|
| API Key 无效 | 重新配置有效的 API Key |
| 网络不通 | 检查服务器网络/代理配置 |
| 余额不足 | 充值 API 账户 |
| 请求超时 | 增加超时时间或重试 |

### 🔴 前端白屏/加载失败

**症状**: 访问网站显示空白页面或 404 错误

**排查步骤**:

1. **检查构建产物**
```bash
# 确认 dist 目录存在
ls -la dist/

# 检查 index.html
head dist/index.html
```

2. **检查 Nginx 配置**
```bash
# 测试配置
sudo nginx -t

# 检查错误日志
sudo tail -f /var/log/nginx/error.log
```

3. **检查静态文件路径**
```bash
# 确认路径配置
location / {
    root /var/www/yh-ai-ppt/dist;
    try_files $uri $uri/ /index.html;
}
```

**解决方案**:
```bash
# 重新构建前端
npm run build

# 重启 Nginx
sudo systemctl restart nginx
```

### 🔴 支付功能异常

**症状**: 支付按钮无反应或提示支付失败

**排查步骤**:

1. **检查 Mock 模式**
```bash
# 查看环境变量
grep MOCK_MODE .env

# 开发环境应该为 true
# 生产环境应该为 false 且配置了真实密钥
```

2. **检查支付配置**
```bash
# 检查支付宝配置
grep ALIPAY .env

# 检查微信配置
grep WECHAT .env
```

3. **查看支付日志**
```bash
docker-compose logs backend | grep -i "pay\|order"
```

**解决方案**:
- 开发环境: 确认 `*_MOCK_MODE=true`
- 生产环境: 确认已配置真实商户密钥

### 🔴 502 Bad Gateway

**症状**: Nginx 返回 502 错误

**排查步骤**:

1. **检查后端服务**
```bash
# 查看后端是否运行
docker-compose ps backend

# 检查后端日志
docker-compose logs backend --tail=50
```

2. **检查端口映射**
```bash
# 确认后端监听端口
docker-compose exec backend netstat -tlnp

# 测试本地连接
curl http://localhost:1111/api/health
```

3. **检查 Nginx 代理**
```bash
# 查看 Nginx 配置
cat /etc/nginx/conf.d/default.conf | grep -A 5 "location /api"
```

**解决方案**:
```bash
# 重启后端服务
docker-compose restart backend

# 重启 Nginx
sudo systemctl restart nginx
```

---

### 🔴 内存不足 (OOM)

**症状**: 服务崩溃，日志显示 "Killed" 或 "Out of memory"

**排查步骤**:

1. **查看内存使用**
```bash
free -h

docker stats --no-stream
```

2. **查看系统日志**
```bash
sudo dmesg | grep -i "out of memory"
```

**解决方案**:

```bash
# 方案1: 增加 Swap
sudo fallocate -l 2G /swapfile
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile

# 方案2: 限制容器内存
docker-compose.yml:
services:
  backend:
    mem_limit: 1g
    memswap_limit: 2g
```

## 数据恢复

### 数据库恢复

```bash
# 1. 停止服务
docker-compose down

# 2. 备份当前数据库（如果存在）
cp server/prisma/prod.db server/prisma/prod.db.corrupted

# 3. 恢复备份
cp /backups/yh-ai-ppt/prod_20240216_030000.db server/prisma/prod.db

# 4. 验证
cd server
npx prisma validate

# 5. 启动服务
docker-compose up -d
```

### 文件恢复

```bash
# 恢复上传文件

chown -R www-data:www-data /var/www/yh-ai-ppt/uploads
```

## 紧急处理

### 服务完全宕机

```bash
#!/bin/bash
# emergency-restart.sh

echo "Starting emergency restart..."

# 1. 停止所有服务
docker-compose down

# 2. 清理缓存
docker system prune -f

# 3. 恢复数据库（如果损坏）
if [ ! -f "server/prisma/prod.db" ]; then
    echo "Restoring database..."
    cp /backups/yh-ai-ppt/prod_latest.db server/prisma/prod.db
fi

# 4. 重新构建
docker-compose build --no-cache

# 5. 启动服务
docker-compose up -d

# 6. 检查状态
sleep 5
docker-compose ps

echo "Emergency restart completed"
```

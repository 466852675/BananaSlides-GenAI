# 数据存储与数据库设计方案 (Data Architecture Design)

> **文档版本**: v1.1
> **生成时间**: 2026-01-19
> **核心一致性**: 匹配 `schema.prisma` 与后端初始化逻辑。

---

## 1. 核心存储架构概览

本项目采用 **混合存储架构 (Hybrid Storage Architecture)**，旨在通过 SQLite 处理高频业务逻辑，通过本地文件系统承载大体量多模态资源。

| 存储层级 | 技术选型 | 职责描述 |
| :--- | :--- | :--- |
| **元数据存储** | **SQLite** (Prisma ORM) | 存储核心业务数据：项目结构、模板配置、用户设置、关联关系。 |
| **文件存储** | **Local Filesystem** | 存储 `/server/uploads/` 下的所有图片、临时 PDF 及导出的 PPTX 原型。 |
| **运行时配置** | **Database + .env** | `AppSettings` 表在启动时会自动与 `.env` 同步，提供热更新与持久化能力。 |

## 2. 数据库表结构 (Database Schema)

### 2.1 项目管理
- **`Project`**: 根实体。
    - `globalConfig`: 存储 `StyleConfig` JSON。
    - `styleMap`: 存储页面类型到参考图 URL 的映射。
    - `status`: 追踪 `idle`, `generating`, `completed`, `error` 状态。
- **`ProjectSnapshot`**: 增量备份表。
    - `version`: 递增版本号。
    - `summary`: 由 AI 生成的变更摘要，用于“时间机器”历史回溯。
    - `data`: 存储当时项目状态的完整 JSON 副本。

### 2.2 幻灯片内容
- **`Slide`**: 单个页面实体。
    - `pageType`: 关键多态字段 (`cover`, `directory`, `transition`, `content`, `end`)。
    - `variants`: 存储 AI 生成的多个视觉版本（JSON 数组）。
    - `brief`: 存储大纲生成的简化上下文。
    - `content`: 存储最终生成的详细 Markdown 正文。
    - `previewUrl`: 当前用户点击选中的图像版本。

### 2.3 模板与偏好
- **`StyleTemplate`**: 公共/系统模板。包含推荐权重 (`isRecommended`) 和使用统计。
- **`Favorite`**: 用户收藏夹。存储用户点击“收藏”时的完整样式快照。

### 2.4 系统级
- **`AppSettings`**: 全局设置单例。
    - `id`: 固定为 `global`。
    - `config`: 包含 AI 服务商、模型 ID、并发限制、语言首选项等。

---

## 3. 文件存储规范

- **存储根路径**: `server/uploads/`
- **子目录**:
    - `uploads/images/`: 存储 AI 生成的背景图。
    - `uploads/temp/`: 存储上传待处理的原始文档。
- **访问逻辑**: 前端通过静态文件服务器访问相对路径。数据库仅记录文件名或 `/uploads/` 开头的相对路径。

---

## 4. 关键同步逻辑

### 4.1 环境配置双向同步 (Hybrid Config Sync)
系统启动（`app.ts` 初始化）或用户修改设置时：
1.  **加载优先级**: `.env` (最高) > `AppSettings` 数据库表 (持久化) > 默认常量。
2.  **自动修复**: 如果数据库中缺失关键 Key（如 API Key），会自动从环境变量补全并回刷入库。

### 4.2 级联删除机制
- `Project` 被删除时，其关联的所有 `Slide` 和 `ProjectSnapshot` 将通过 Prisma 的 `onDelete: Cascade` 机制自动清除，防止数据孤岛。

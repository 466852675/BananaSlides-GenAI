## 1. 大纲生成核心逻辑 (Core Logic)

在生成 PPT 大纲时，系统不仅要求 AI 提供内容，还强制要求其遵循精确的**结构占比**与**页面序列**。

### A. 动态占比校准 (Structure Calibration)
后端在发送请求前，会确保 `targetPageCount`（目标总页数）与各类型页面之和绝对相等：
- **公式**: `content = targetPageCount - (cover + directory + transition + end)`。
- **降级**: 确保 `content` 至少为 1。

### B. 页面顺序引导 (Sequence Guidance) —— *最新特性*
为了防止 AI 乱放“目录”或“过渡页”，Prompt 会注入明确的【推荐页面顺序指南】：
- **规则**:
    1. 封面 (Cover) 置顶。
    2. 目录 (Directory) 紧随封面。
    3. 内容页 (Content) 与 过渡页 (Transition) 交叉均匀分布。
    4. 结束页 (End) 置底。

---

## 2. Prompt 模版 (Standard Template)

```markdown
Task: 为主题 "${topic}" 生成一份结构化的 PPT 演示大纲。

【严格限制】:
1. 总页数必须正好为: ${targetPageCount} 页。
2. 页面组成结构必须严格遵守以下配比:
   - 封面页 (cover): ${structure.cover}
   - 目录页 (directory): ${structure.directory}
   - 章节过渡页 (transition): ${structure.transition}
   - 内容正文页 (content): ${structure.content}
   - 结束页 (end): ${structure.end}

【推荐页面顺序指南 (必须遵守)】:
- 第 1 页: cover, 第 2 页: directory, ..., 第 N 页: end

【关键规则】:
- 如果某个页面类型的数量为 0, 则严禁生成该类型的页面。
- 每个对象必须包含: title, brief (核心观点), pageType。

【输出格式】:
- 返回一个 JSON 数组，严禁包含 Markdown 代码块。
```

---

## 3. 详细内容生成 (Detailed Content)

当大纲确认后，每一页的“详细正文”生成遵循以下字数控制：
- **正文页 (content)**: 150-250 字。要求包含 bullet points、核心论据。
- **结构化页面 (structural)**: 50-100 字。保持精炼。

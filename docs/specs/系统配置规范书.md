# ⚙️ 系统配置规范书 (System Configuration Spec)

> **文档版本**: v2.0 (深度重构版)
> **技术对齐**: `server/src/services/setting.service.ts`
> **核心机制**: 多级配置互刷与并发调优

---

## 1. 配置互刷协议 (Config Synchronization)

系统通过 `AppSettings` 模型维护全局运行状态，并执行双向同步逻辑。

### 1.1 环境变量优先权
启动时，`syncEnvToDatabase` 函数执行以下逻辑：
- **检测**: 扫描根目录 `.env`。
- **对齐**: 若环境变量中存在 `GEMINI_API_KEY` 或自定义 `BASE_URL`，系统将**强制改写**数据库中的全局配置，确保运维人员的紧急调整具有最高权威。

### 1.2 热重载触发流程 (Hot Swap)
1.  用户通过配置面板点击“保存”。
2.  后端更新 `AppSettings` 记录。
3.  系统触发全局缓存刷新。
4.  后续的 `getTaskConfig` 请求将即时捕获新模型 ID。

## 2. 工业级并发控制 (Concurrency Engine)

为了在速度与 API 稳定性（429 Rate Limit）之间取得平衡，系统硬编码了不同的并发策略：

- **Text Concurrency (3-5)**: 逻辑推理较快，支持少量并发。
- **Image Concurrency (1)**: **串行锁定。** 由于生图模型（如 DALL-E-3 或 Gemini Image）耗时极长且对并发限制严苛，系统强制采用队列式串行渲染，确保 99.9% 的生成成功率。
- **Vision Concurrency (2)**: 视觉解析属于中等开销，支持双线程并发。

## 3. 分辨率驱动策略

系统根据应用场景动态调整生成的分辨率：
- **Preview (预览)**: 1024px。
- **Standard (标准)**: 2K (1792x1024)。
- **Ultra (导出)**: 4K (使用 AI 超分或原生 4K 生成)。

## 1. 核心链路集成: `generateSlideVariant`

在业务层调用图片生成函数时，必须确保上下文参数的完整性，以激活后端的“智能风格匹配”系统。

### A. 关键参数映射
| 参数名 | 说明 | 获取来源 |
| :--- | :--- | :--- |
| `pageType` | 页面类型 (cover/content/...) | `GeneratedSlide.pageType` |
| `fullContent` | 完整业务正文 (不截断) | `GeneratedSlide.textContent` |
| `globalStyleMap` | 全局页面风格映射表 | `Project.styleMap` |
| `allSlideTitles` | 本项目所有页面标题 | `projects.items.map(i => i.title)` |

---

## 2. 后端模型路由逻辑 (`getTaskConfig`)

后端具备动态模型协商能力，优先顺序如下：
1.  **CustomCombo**: 用户在全局设置中指定的针对特定任务（Text/Image/Vision）的独立 Connection。
2.  **General API Settings**: 通用设置中的模型 ID。
3.  **Adaptive Default**: 若上述均缺失，系统将智能路由（Text -> `pro-preview`, Vision -> `flash`）。

---

## 3. 视觉预采样机制 (analyzeStyleImage)

为解决 DALL-E 等模型“无法直接看图”或 Gemini 原生视觉理解费用较高的问题，系统采用了：
- **前置采样**: 仅在 `styleRef` 变更或首次生成时调用 Vision 模型分析构图关键词。
- **降级保护**: 若采样失败，系统会自动回退到基于文字描述的 `Fallback` 模式。

---

## 4. UI 交互规范

### 4.1 胶囊导航栏 (Capsule Header)
- **触发逻辑**: 监听页面滚动，`scrollY > 20` 时激活。
- **实现方式**: `src/App.tsx` 中的 `isScrolled` 状态控制 Tailwind 类组切换。

### 4.2 级联过滤器 (Cascading Filter)
- **定义**: 位于 `src/components/Dashboard.tsx`。
- **注意**: 历史库中的过滤器需确保 `customOptions` 是从已有项目数据中动态聚合提取的，以保证“所见即所得”的筛选体验。
